## W1 探针结论（qwen3.7-flash，2026-09-18）

- 供应商文档：隐式缓存自动、前缀 ≥ 1024 token、命中按 20% 计费、不保证命中；显式缓存为内容块内 `cache_control: {type: ephemeral}`，≥ 1024 token、5 分钟有效且命中后重置，创建 125%、命中 10%，最多 4 个标记、回看 20 个内容块；两者对单个请求互斥；工具定义算作系统消息的一部分。
- 实测：逐字节相同的请求 5/5 命中（128 token 对齐，约不含最后一条消息）；系统消息内任何改动（末尾加一行、工具换序、提醒移出或改数字）都是 0，即使前 1,000—1,944 token 相同。
- C 为何为 0：现布局每次调用都改写首条系统消息，按上条规则不可能命中。B 的 5.2% 是每次恰好 1280 token 的固定命中，等于 B 的工具 714 + 静态提示 632 + 模板 17 按 128 取整，属于供应商对共享前缀的未公开行为，探针复现不了（B 下一步 0），C（926 + 1018）从未出现，不能依赖。
- 稳定系统消息 + 只追加历史后，隐式命中逐步仍不稳定（4 次中 1 次）；显式标记打在最新一条历史消息上则逐步确定命中整段旧前缀，创建只计增量（命中 1949→2272→2394，创建 323/122/144）。
- AgentScope 的 `cacheControl(true)` 把标记写成消息级字段并打在最后一条消息上：百炼忽略消息级字段（0 创建 0 命中），最后一条又是易变提醒。
- 决定：首条系统消息只放静态提示；提醒作为末尾临时 user 消息（不进记忆）；研究调用在系统消息与最新一条历史消息上打显式标记，由传输层改写为内容块形式并读取 `cache_creation_input_tokens`。
