## 为什么先做小样本

原始调研工作簿约 27 MB，包含多个工作表、图片和不同业务主题。直接摄取整份文件会同时引入解析、分块、检索范围、模型回答和业务口径等变量：即使结果失败，也很难判断问题发生在哪一层；即使个别问题答对，也不能证明复杂工作簿已经得到可靠支持。

因此先选择一个可人工逐格核对的有限区域，同时制作 XLSX 和 Markdown 两种表达，回答两个更小的问题：项目原生 Excel 链路能否保留关键事实，以及格式变化是否会影响这个样本的检索与回答。该实验不是为了建设通用 Excel 转换器，也不把小样本结果外推为完整 Office 解析能力。

## 样本选择与处理

选择来源工作表“浓度检测（双场景）”的 `B2:I26`，因为有限区域内同时包含定义、单点事实、计算公式、顺序步骤和两个场景的差异，适合覆盖不同问法。所选区域之外的图片、排班表和其他工作表均不进入本实验。

派生 XLSX 由新工作簿重建，只保留所选区域的显示值、必要合并关系和行序；逐单元格核对与来源显示值一致。文件只有一个工作表和 `A1:H25` 有效区，不包含图片、公式、批注、超链接、作者或最后修改者信息。Markdown 只重组表达结构，没有增加来源中不存在的数值、设备型号或业务规则。

## 评测方法

- 两种格式依次进入同一个临时知识库，任一时刻只保留一种格式，避免两份等价内容互相影响召回。
- 摄取参数固定为 `parseProfile=fast`、`maxChars=1024`、`overlapChars=128`、`rowsPerChunk=50`、`toleranceFactor=3`。
- 固定检查六类事实：浓度定义、偏高/偏低调整、浓度壶净重公式、烘干称重公式、`105±5 ℃` 和中心实验室与现场差异。
- 每种格式各运行 8 道独立问题：6 道可回答题覆盖定义、步骤、公式和场景差异；2 道不可回答题检查是否会编造允许误差、品牌或型号。
- 每题使用新会话。可回答题必须同时满足“目标片段被召回、答案与证据一致、来源文件正确”；不可回答题必须明确说明资料未提供。
- 运行故障可以在查明原因后重试一次，内容失败不能通过改问题、重复采样或调参掩盖。

## 发现的问题

### 1. 有限样本可用不等于完整工作簿可用

原生 `ExcelDocumentParser` 能处理这一个规整表格样本，但当时仍按“一工作表一张表、首行作为表头”的方式理解内容，不能证明它能正确处理原工作簿的图片、多语义分区和其他复杂工作表。

### 2. Markdown 分块更少，但没有回答质量优势证据

XLSX 生成 9 个块，Markdown 生成 2 个块；两者都保留六类事实并通过相同问题。该差异只说明这个样本的 Markdown 结构更紧凑，不能从 8 道题推导 Markdown 的回答质量更高，也不足以要求人工转换完整工作簿。

### 3. 检索范围存在跨知识库污染

XLSX 和 Markdown 各自的 8 次检索与来源列表都混入既有教程文档 `IT支持.md`。目标证据仍被召回，回答没有据此生成错误结论，所以没有修改预先约定的通过条件；但这暴露了知识库范围不纯，后续不能只看“答案是否答对”，还必须检查来源和上下文纯度。

### 4. 来源粒度和原文口径仍有限制

当时 `SourceRef` 只保证文档级来源，因此本实验只验收到正确文件名，不宣称已经支持工作表、单元格或条款级引用。烘干称重公式在原材料不同位置的“湿重/干重”与“矿浆/矿样质量”表述也未完全闭合；实验按固定原文验收，没有自行补造采样桶扣重规则或把演示口径写成正式规程。

## 效果与外推边界

本实验建立了第一个可人工核对的领域样本基线，证明原生 XLSX 和受控 Markdown 都能在这个有限区域中保留目标事实并支持正确回答，同时提前暴露了跨知识库混入问题。后续精确来源、严格检索范围、完整工作簿解析和系统化评测因此有了可追溯的起点。

结论严格限定为“一个工作表有限区域、8 道固定问题”：

- 不代表支持原始 27 MB 工作簿的全部 12 个可见工作表、图片和复杂布局。
- 不代表 Markdown 普遍优于 XLSX，也不要求把企业原文件人工转换为 Markdown。
- 不把 Q1–Q6 全部答对写成工业领域通用准确率；后续正式比较使用独立的 3 类文档、24 题评测。
- 不因目标证据已命中而忽略 `IT支持.md` 混入；来源纯度必须作为独立问题处理。

## 数据与回滚

- 原始企业工作簿继续位于 Git 忽略目录，不随仓库发布；Git 中只保留已确认可公开的两个有限派生样本。
- 两个派生文件属于提交 `a016f01`，但该提交还包含工业知识闭环和 ROS1 dry-run 等其他实现；不应为了移除样本而整体回退该提交。
- 如需替换样本，应保留新的来源范围、逐格核对结果、SHA-256 和人工确认记录，并重新执行相同问题集；不能直接覆盖旧样本后继续引用本页结果。
