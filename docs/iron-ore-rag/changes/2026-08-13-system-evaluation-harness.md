## 问题与边界

阶段 1 只证明一个规整工作表样本可用，无法为简历提供完整工作簿、原生 PDF、异常文本层 PDF、意图路由和拒答的统一数字。本改动建立一个可冻结、可审计的小型评测，但不把 3 份文档和 24 道题外推为行业基准。

不改冻结基线源码，不建设通用 Excel 转换器，不测试已废弃的 `ChunkerSettings.strategy`，不接入真实机器人，不把 OCR、检索和回答指标混成一个“准确率”。

## 实施内容

- 新增 [`eval/iron-ore/README.md`](../../../eval/iron-ore/README.md) 和固定运行手册，定义 B0/B1/B2/C0/C1/C2/C-final 七个实验臂。
- 外部工具复用两版已有的 `/rag/eval` 和 `/rag/v3/chat`，完成知识库导入、解析锚点、检索、完整 SSE、意图切换、盲评、固定门槛选型和快照归档。
- 真实数据留在 `local-data/eval/`：24 道题由 18 道单文档题、3 道近领域混淆题和 3 道不可回答题组成；另有每份文档 5 个解析锚点。
- 基线和当前版继续使用独立数据库、Redis DB、MQ 后缀和对象存储桶；固定单一 Chat、Embedding、Rerank 候选，禁止静默降级。
- 专用意图 SQL 只创建两个 KB 意图，同时兼容 `bcfba62` 和当前 Schema；切换工具只操作评测 ID 和对应 Redis 逻辑库。
- 快照、恢复和意图切换工具支持在项目 Compose 容器内调用 PostgreSQL/Redis 客户端，不要求宿主机安装 `psql`，也不把密码拼进命令。

### 已暴露问题

- XLSX 的 123 个块平均 1,573 字符，70 块超过 1,024 字符目标，16 块超过 3 倍容差，最大 12,489 字符；精确重复块比例约 13.8%。默认预算对复杂工作表不是硬上限。
- B0 原生 PDF 仅恢复 3/5 个解析锚点，并对应最低的分族 Hit@5（83.3%）和 Context Precision（7.3%）。
- B1 虽有 17/18 的意图 Top-1 正确，但未改善 Hit@5，全部锚点 Hit@5、路由纯度和 P95 反而变差，说明分类准确不等于检索收益。
- B0 的总体 Context Precision 只有 16.7%，且运行日志出现个别 15 秒向量通道超时；后续应优先检查改写拆分、范围补充和长块，而不是只增加 TopK。
- C1 表明分类 Top-1 达到 100% 仍不能保证路由纯度提升；需要逐题检查作用域正确但上下文排序变差的案例，而不是继续增加意图数量。
- C0/C-final 的同配置波动说明当前 24 题一次运行不足以估计稳定差异。下一轮若要形成更强简历结论，应先固定改写采样或进行至少三次重复运行，再报告均值与离散度。

原始结果位于 `local-data/eval/runs/B0`、`B1`、`B2`；干净 seed、B0 和 B2 均有不可覆盖的 manifest 与 PostgreSQL custom-format dump。最终已把 `ragent_eval_baseline` 恢复至 B0：2 库、3 文档、141 块/向量、0 意图、24 条成功 trace，Redis DB14 已清空且 9091 已停止。

当前版原始结果位于 `local-data/eval/runs/C0`、`C1`、`C2`、`C-final`；人工得分与脱敏摘要位于 `local-data/eval/review/score-v1.json` 和 `evidence-summary-v1.md`。current seed、C0、C2、C-final 均有不可覆盖的 manifest 与 PostgreSQL custom-format dump。冻结评测结束时 `ragent_eval_current` 停留在 C-final；后续优化另建 D0/D1 结果并将运行态数据库保存为 D1 快照，没有覆盖这里的 C-final 文件和 dump，详见[请求级检索预算与结构化重排](2026-08-13-request-level-retrieval-purity.md)。

## 数据与兼容性

- 无产品数据库迁移、无公共 API 变化、无基线源码变化。
- 真实问题、标准事实、原始响应和 PostgreSQL dump 不进入 Git。
- OCR 或分块参数变化需要恢复各自 seed 并重新入库；意图开关只改两条意图、清对应 Redis 后重启。
- `restore_eval_database.py` 仅允许两个 `ragent_eval_*` 名称，且要求 `--yes-replace` 和完整数据库名双重确认。
