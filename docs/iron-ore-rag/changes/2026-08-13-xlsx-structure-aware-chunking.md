## 改动目的

把规则型 XLSX 转换为长度受控、无解析器制造的重复项、仍保留表头语义和单元格范围的检索块。目标不是追求更大的召回数量，而是先修复输入表示，使 embedding 和 rerank 面对的是可区分、可引用的业务单元。

## 问题如何发现与边界

系统评测对冻结 C-final 索引执行 chunk 审计时发现：同一 XLSX 生成 123 个块，其中 70 个正文超过目标 `1,024` 字符，最大 12,489 字符；17 个是多余的精确重复块，比例约 13.8%。按块回溯到 Sheet 和单元格范围后，最长块和最大重复组都对应合并单元格展开区域，说明问题来自解析和装配，而不是题目不足或 TopK 太小。

本次只修复已有规则型 XLSX 解析与通用块装配中的可证实问题。不建设任意复杂工作簿转换平台，不修改冻结题集，也不把离线块形状改善提前写成回答准确率或 Context Precision 提升。

## 根因

1. 数据区的合并值被复制到区域内每一行、每一列。横向合并的长说明因此在同一行重复多次；完全合并的纵向续行又产生相同块。
2. 表格分块只按 key-value 向量正文估算长度，没有同时计算最终 Markdown 正文和章节路径前缀；整表小于 3 倍容忍上限时还会放宽到容忍值。
3. `ChunkPacker` 会把表格 chunker 已切开的 piece 再次合并，也可能为凑最小长度跨工作表合并小尾块，导致来源作用域和长度预算一起失真。

## 候选方案与选择理由

- **增大 TopK**：只能返回更多已经膨胀或重复的块，不能修正块内结构，还会增加上下文噪声和 rerank 成本，因此排除。
- **超过上限直接截断**：可能截掉业务字段、步骤或来源范围，使回答看到不完整事实，且无法处理重复块，因此排除。
- **按固定字符数切分**：会把表头与数据行、键与值、Sheet 与单元格范围拆开，虽然长度变短，但检索文本和引用语义会失真，因此排除。
- **结构感知归一化与分块**：在表格语义仍可见时处理合并区域、稀疏宽行、双文本预算和上游 piece 边界，能够同时修正根因并保留来源信息，因此采用该方案。

## 实施内容

- `ExcelTableNormalizer` 对表头和数据使用不同的合并规则：表头继续横向展开以保留父子列名；数据行只在合并区域第一列携带一次值。
- 只折叠“原工作表整行为空、由纵向合并展开后与上一行相同”的续行，并把来源范围扩展到完整合并区域；用户主动录入的相同记录仍保留。
- `TableChunker` 同时以最终 Markdown 正文和带章节路径的 embedding text 为 1,024 字符预算依据。
- 对“很多空列、少数非空长字段”的稀疏宽行按非空列组合成窄表片段，字段文本和原始单元格范围不丢失。只有单个不可再拆的键值对自身超限时允许保留原子超限块。
- `ChunkPacker` 尊重上游 piece 边界，限制引导内容和小尾块合并后的实际长度，并禁止跨顶级章节/工作表合并。

## 改动效果

### 分块与摄取效果

| 指标 | 冻结 C-final 索引 | 修复后离线 / D1 在线结果 |
| --- | ---: | ---: |
| XLSX 块数 | 123 | 79 |
| 正文平均字符数 | 1,573.2 | 843.5 |
| 正文 P95 | 未记录 | 1,013 |
| 正文最大字符数 | 12,489 | 1,019 |
| 正文超过 1,024 | 70 | 0 |
| embedding 最大字符数 | 11,916 | 1,017 |
| embedding 超过 1,024 | 32 | 0 |
| 多余精确重复块 | 17 | 0 |
| XLSX 固定解析锚点 | 5/5 | 5/5 |

修复后的离线结果与 D1 在线审计完全一致，说明代码路径和真实重建结果一致。可以直接归因于本改动的是：超长块 `70 → 0`、多余精确重复块 `17 → 0`，同时固定解析锚点保持 `5/5`。

D1 的 XLSX 摄取总耗时由 C0 的 `11.3 s` 变为 `7.0 s`，其中 embedding 由 `10.3 s` 变为 `6.3 s`；这只是同机各一次运行，只记录现象，不作为稳定性能结论。

### 检索观察，不作单因果归因

D1 继续使用冻结 24 题。XLSX 六题的锚点 Hit@5（至少一个）保持 `100%`，Context Precision 相对 C-final 从 `27.9%` 变为 `39.3%`，Anchor Recall 从 `100%` 变为 `94.4%`。缺失锚点对应的正确块仍在索引中，但在三子问题请求的最终配额中没有入选；详细归因见[请求级检索预算与结构化重排](2026-08-13-request-level-retrieval-purity.md)。因此这里可以认定块形状和重复问题已消除，但不把单次 D1 写成稳定检索提升。

## 限制与停止状态

- 真实验证只覆盖一个企业工作簿；规则能够处理本文件中的多行表头、合并区域和稀疏宽行，但不能据此外推为任意复杂 Excel 支持。
- 单个不可再拆的键值对若自身超过预算，仍保留为原子超限块，避免截断业务事实；新的工作簿形态必须先增加对应回归样本。
- D1 的检索变化同时包含请求级预算与结构化 rerank 改动，不能全部归因于 XLSX 分块。
- D1 暴露的请求级空位后来在 D2 中用固定改写和公平回填单独验证；机制能够填满 TopK，但质量 gate fail，开关保持默认关闭并停止本轮调参。该负结果不改变本次分块形状修复已经通过的结论。
