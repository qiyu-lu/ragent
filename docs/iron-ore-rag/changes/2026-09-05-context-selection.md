# 固定候选上下文选择实验：简单基线已足够，覆盖策略停止

## 问题与边界

历史 D0/D2 表明请求级预算和重复回填会改变上下文纯度，但没有证明覆盖感知算法能提高回答质量。本轮只检验一个更窄的假设：在候选池和上下文预算固定时，显式要点覆盖和去重复是否比前缀、统一重排或简单 MMR 保留更多完整证据。

实现和新实验使用 `CS-*` 标签，未修改 B0～D2 文件、数据库快照、旧索引或机器人链路。Java 选择模块只接到本地 gold-free JSONL 回放入口，没有接入默认聊天路径，所以当前产品行为仍是 legacy。

## 数据冻结与 P0 诊断

数据来自 [HotpotQA 官方协议](https://github.com/hotpotqa/hotpot)：distractor 模式每题给定 10 个候选段落及句级 supporting facts，许可为 CC BY-SA 4.0。本环境访问 CMU 原始下载服务器 30 秒超时，因此改用 `hotpotqa/hotpot_qa` Hugging Face namespace 的 Parquet 镜像，固定 revision `1908d6a` 并逐文件校验 SHA-256。

按种子 `20260905` 从官方 train 抽 200 条开发题、官方 dev 抽 400 条本地冻结测试题，保持 bridge/comparison 比例。开发题中移除了与测试题共享支持文档的样本，最终跨 split 支持文档重叠为 0。源数据另有 22 条 train 和 1 条 validation supporting-fact 位置越界，抽样前显式排除；固定数据集 schema 与证据定位校验为 600/600 通过。

1024 本地估算 token、最多 10 块时，200 条开发题的完整 gold 都在候选中且存在可容纳组合。按原问题 BM25 重排的 CS-R 仍有 16/200（8.0%）未保留完整证据，达到“至少 10 例且 5%”的继续门槛。来源顺序前缀 CS-P 有 21/200，但它不作为唯一排序基线。这只证明固定公共候选存在选择空间。

## P1/P2 实现

新增候选快照同时保存原问题、最多四个显式要点、稳定候选 ID、正文和 ranking text 哈希、来源顺序/分数、原问题及要点分数矩阵、评分是否执行、向量、渲染 token、代码/数据/配置/模型身份和降级说明。gold 答案、expected facts 和 evidence requirements 不进入快照或 Java 输入；评分程序在选择完成后另行读取标签。

Java 中只有一套选择实现，Python 负责数据、启动 Java 回放和统计：

- CS-P：来源前缀加预算守卫；
- CS-R：原问题统一相关性排序后加预算守卫；
- CS-M：相关性减冗余的增益/token 贪心；
- CS-C：相关性、各要点最大覆盖增益和冗余惩罚的增益/token 贪心；
- `CS-C-no-cover` 与相同 μ 的 CS-M 共用实现，`mu=0` 是 no-diversity 消融。

分数先在每个问题/要点内部转换为确定性排名权重，不把不同问题的 raw score 混为同一量纲，也不称为支持概率。预算装不下的块会跳过；无正增益时停止；并列按稳定 ID；最终按原问题相关性顺序渲染。数字或版本不同的高相似块不会被当成完全重复。

本轮数据没有在线模型快照。开发特征明确标为 BM25、256 维 signed hashing 和本地 token 估算，只用于离线机制筛选。

## P3 开发结果与停线

开发参数在看结果前固定：CS-C 为 λ=`0.5/1.0/2.0` 与 μ=`0/0.1/0.3/0.5` 的 12 组组合；MMR 获得 4 组 μ。主结果如下：

| 臂 | 完整证据覆盖 | 证据召回 | 平均本地估算 token | 平均块数 |
| --- | ---: | ---: | ---: | ---: |
| CS-P | 179/200（89.5%） | 94.58% | 898.54 | 9.15 |
| CS-R | 184/200（92.0%） | 96.29% | 899.35 | 9.14 |
| CS-M，μ=0 | 198/200（99.0%） | 99.50% | 872.22 | 9.34 |
| CS-C，λ=2、μ=0 | 198/200（99.0%） | 99.50% | 873.20 | 9.34 |
| CS-M，μ=0.3 | 126/200（63.0%） | 80.43% | 363.96 | 4.19 |

最佳 CS-C 与最强简单基线逐题完全打平：改进 0、退化 0，完整覆盖差为 0 个百分点。μ 增大后，冗余惩罚和“无正增益即停止”使选择器过早停止，省 token 的同时丢失大量必要证据。

预先约定的预算敏感性也不支持继续：

| 预算 | 简单基线 | CS-C | 差值 |
| ---: | ---: | ---: | ---: |
| 512 | 159/200（79.5%） | 160/200（80.0%） | +0.5 个百分点 |
| 1024 | 198/200（99.0%） | 198/200（99.0%） | 0 |
| 2048 | 200/200（100%） | 200/200（100%） | 0 |

因此未达到“相比最强简单基线至少 +5 个百分点”的开发 gate。400 道公共冻结测试、端到端回答、在线延迟/费用和生产接入均按计划停止，legacy 保持默认。

## 成功、失败与可陈述结论

CS-P 的目标失败例包括 `5adce07e…`（Michael Robert Sutton 所在大学学生数）、`5a873d9c…`（两部歌剧首演时间比较）和 `5ac437f3…`（Edison Building 名称来源人物的发明）。简单基线修复了前两类中的多数选择缺口。

简单基线的成功例包括 `5ac3bb80…`（Developing Communities Project）、`5adce07e…` 和 `5a8766bf…`（Dark Fantasy hook）。它仍在 `5ade9a80…`（William Sharp McKechnie）和 `5ae53413…`（Rainbow/Jason Hartless）两题丢失完整支持证据；实际失败不足 3 条，按真实数量保留。

可陈述的结论是：在这 200 道 HotpotQA 固定候选开发题和离线代理特征下，按相关性/token 的简单贪心已达到 99.0% 完整证据覆盖，显式覆盖项没有达到继续门槛。它不是 HotpotQA 官方成绩，不是全库召回提升，也不证明中文工业回答准确率提高。
