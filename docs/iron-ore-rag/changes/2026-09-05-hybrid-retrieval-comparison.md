# BM25、RRF 与向量检索：配对实测

## 做了什么

用户希望直接比较成熟检索方案，不再围绕单个失败案例反复调参。本轮复用原项目 Elasticsearch BM25、PGVector、Java RRF 和百炼 qwen3-rerank，开启**隔离评测配置**，没有修改默认聊天通道。

新增仅评测 profile 可用的配对接口：先由原检索引擎运行向量 + BM25 + RRF + 重排，保留两路原始候选；再使用同一批候选分别运行向量重排和 BM25 重排。每题得到六个方案，共享真实向量召回，避免不同运行的 embedding 超时干扰配对。

固定参数：每路召回 40，RRF 常数 20、等权，融合候选池最多 40，最终最多 10 块；Qwen3-Embedding-8B / 1536维 / PGVector，ES 8.15.5 英文分析器和 BM25，qwen3-rerank。问题不改写，不生成回答；不搜索模型或权重。混合方案多一路召回，不能声称计算量与向量单路相同。

选择依据参考 [Elastic 的混合检索说明](https://www.elastic.co/docs/solutions/search/hybrid-search)：BM25 与向量可以互补，RRF 用排名融合；这是一条成熟路线，但是否适合本项目仍看实际数据。

## Hotpot 开发池：200 题

1,988 篇公开正文，1,991 个实际块，向量与 BM25 使用相同 ID 和正文。200/200 配对请求健康，无 HTTP 错误。指标为一题全部来源限定支持句在前 K 块中的完整覆盖率，不是回答准确率。

| 方案 | Top5 完整题数 | Top10 完整题数 | Top10 完整率 |
| --- | ---: | ---: | ---: |
| 向量 | 164 | 184 | 92.0% |
| BM25 | 113 | 151 | 75.5% |
| 向量 + BM25 → RRF | 146 | 181 | 90.5% |
| 向量 + 重排 | 174 | **187** | **93.5%** |
| BM25 + 重排 | 169 | 181 | 90.5% |
| RRF 混合 + 重排 | 172 | 185 | 92.5% |

RRF 混合 + 重排相对向量 + 重排：改善 0 题、退化 2 题，净差 -1 个百分点。向量与 RRF 的 Top40 完整覆盖均为 197/200，BM25 为 182/200；本池没有表现出默认开启 BM25 的收益。

不能把本轮 187/200 与上一轮 CS-LIVE 的 182/200 比较为算法提升：上一轮有 5 次向量通道超时，本轮配对没有该失败。应比较本轮同一候选来源的各臂。

## 更大公开基准：BEIR SciFact

来自 [BEIR 官方发布](https://github.com/beir-cellar/beir)：完整 5,183 篇论文摘要、官方 test 300 道查询。归档 MD5 与官方一致（`5f7d1de60b170fc8027bb7898e2efca1`）。全部真实入库为 5,438 块，关系块/向量/ES 逐 ID 一致，无入库失败。

参数在读取评分结果前固定；test qrels 只供独立评分，没有传给线上检索或模型。该基准是科学论断到相关论文的检索，不是工业问答。按相同 TopK 块预算选取后映射并去重为源论文，计算 Recall 与 nDCG；不是官方整篇文档 BEIR leaderboard 运行。

300/300 配对请求健康，六臂均完成，结果如下。Recall 是相关论文召回率，nDCG 衡量相关论文的排序质量；二者都不是回答准确率。

| 方案 | Recall@10 | nDCG@10 |
| --- | ---: | ---: |
| 向量 | 87.28% | 0.7303 |
| BM25 | 81.73% | 0.6834 |
| 向量 + BM25 → RRF | 89.41% | 0.7598 |
| 向量 + 重排 | 90.42% | 0.7786 |
| BM25 + 重排 | 87.69% | 0.7696 |
| RRF 混合 + 重排 | **91.66%** | **0.7856** |

混合 + 重排相对向量 + 重排：Recall@10 +1.23 个百分点，nDCG@10 +0.00699。按逐题 nDCG 比较为改善 11、退化 18、不变 271，少数较大改善贡献了均值净增；不能只引用均值而声称全面优于基线，也未做统计显著性声明。

## 选择结论

1. **默认保留向量 + qwen3-rerank。** Hotpot 上它最佳，SciFact 上距最佳很近；当前数据不支持为了很小且跨数据集不一致的收益默认增加 ES 通道。
2. **保留可切换的 BM25 + 向量 + RRF + rerank 配置。** 混合方法在 SciFact 有小幅收益，是已经跑通并有实测的可选能力，不是仅在代码中存在的功能。无需再追加多 Agent 或图检索来“凑技术”。
3. 当前测试只覆盖英文公开正文，没有中文工业领域的混合检索对照；不要声称工业准确率提升、在线时延改善或稳定全面领先。主比较不生成答案，费用按用户要求不是筛选门槛。

整体执行为 200 + 300 = 500 道配对查询，六臂全部完成且健康；每题最多 3 次重排模型调用，原始候选方案无需额外模型调用。这里统计的是应用实验范围，不替代提供商账单。

- 新 Elasticsearch 容器 `ragent-cs-hybrid-es-v1` 仅监听本机 9201，没有使用其他项目的 9200。
- Hotpot 沿用专用评测库；SciFact 使用新数据库 `ragent_eval_pool_scifact_v1`、Redis 12、9094 和独立对象桶/ES 索引，不混入旧业务库。
- 新增 Java 配对接口和脚本，不重新实现生产 BM25/RRF；模型调用结果、原始候选、逐题标签、清单哈希均保留。
- 首次配置检查因 Spring import 优先级未实际打开 keyword 通道，单题失败保留在 `CS-HYBRID-v1`；修正为多文档覆盖配置后正式运行 `CS-HYBRID-main-v1`，没有把配置错误算成算法退化。
- Python 14 项测试通过，Java 相关检索与配对接口 33 项测试通过；检查在一轮集中执行，没有重新展开参数试验。
- 按用户要求不以 API 费用作为限制；应用配对请求不是提供商账单，未伪造费用或实际 token。密钥只由 IDEA 传入进程环境。
- 未使用 academic-research-suite；原 CS-DEV 负结果、CS-LIVE 结果及 Hotpot 冻结 400 题保持不变，未提交/推送。

已停止本轮临时 Java 服务和新 ES 容器；容器未删除，专用数据库、对象桶、Redis 分区、索引和结果都保留可恢复。没有停止其他项目服务。
