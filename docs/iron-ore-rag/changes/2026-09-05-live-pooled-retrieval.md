# CS-LIVE：真实检索阶段诊断

## 目的与实现

将此前 CS-POOL 的本地 BM25/hashing 代理替换为真实解析、切块、SiliconFlow embedding、PGVector 召回和百炼 rerank，检查失效发生在哪一阶段。**本次新增的是诊断能力，不是已验证的新检索算法收益**。旧覆盖策略的 gate fail 不变，默认聊天选择策略不变。

- IDEA `RagentApplication` 中的两项 API 密钥仅通过进程环境复用，不保存副本。
- 新建 `ragent_eval_pool_v1`、Redis DB 13、独立对象桶和 `cs_pool_v1`，服务仅绑定 `127.0.0.1:9093`，未触碰旧 B0～D2 库与结果。
- 1,988 篇公开开发正文全部入库成功，实际产生 1,991 块和 1,991 向量。逐 ID 全连接核对无缺失；481 个不同支持句均可在对应源的真实块中完整匹配。
- RocketMQ 因本机磁盘约 90% 拒绝发送；没有清理用户数据或提高保护阈值。专用同步入口调用原消费者的 `executeChunk`，仅绕过 MQ 调度，不评价异步链路性能。
- 显式请求级 `RetrievalCapture` 捕获通道、处理器和最终 Top10 的不可变快照，不通过线程局部变量传递，不把 gold 传入在线接口。
- 入口有 profile/开关/管理员/独立数据库/唯一公共集合/无外部集合向量保护；单测覆盖关键隔离拒绝路径。

## 固定配置与指标边界

原问题主诊断：无改写、无意图/MCP，只有向量通道，Qwen3-Embedding-8B（1536维），召回 Top40，候选池 40，qwen3-rerank，原请求级 Top10。原公平回填及覆盖选择器均未开启。另运行固定前五题的改写功能冒烟，不进行参数搜索或回答生成。

指标为“一题的全部来源限定支持句是否在选中块中”，不是回答准确率。映射采用 NFC + 去空白的完整句子包含，跨源同句不能替代；不能匹配的句子归入入库/映射不可用，不偷偷移除分母。本轮该项为 0。

这不是官方 HotpotQA fullwiki：仅合并 200 道 public_dev 的给定正文。冻结 400 题未入池、未测；中文草案仍待人工复核。源文件为稳定哈希文件名，原标题在正文中；不是中文工业文件分布。切块参数 1024 字符、重叠 128 字符，与历史 CS-DEV 的 1024 token 选择预算不同，不可直接做跨实验“提升百分点”比较。

Rerank 阶段保存的是“模型 Top10 头部 + 融合尾部”，故其 Top20/40 不是完整模型排序；不能把后续尾部都当作 rerank 打分结果。

## 执行与失败保留

前五题原问题和改写冒烟均 5/5 完整，仅作功能校验。`partial-corpus-smoke.jsonl` 不参与正式指标；旧 `raw-pilot5-score.json` 是采集期间误读的四题结果，保留但作废，完整五题文件为 `raw-pilot5-complete-score.json`。评分器已补充完成清单哈希校验，防止再次误读运行中的文件。

主诊断第 57 题触发 30 秒向量通道超时，保留该首次失败，从第 58 题续跑。第 150～152 题再次连续超时而停批。停批期间只读线程检查未见残留 embedding/PGVector 调用；下一道未执行题恢复正常后继续。不能由此精确归因于某个外部提供商故障。所有失败不重试、不替换，超时和检索参数不变；续跑只把连续失败停批阈值从 1 调为 3。

最后一段第 15 题（总第 168 题）另有一次向量通道超时，随后恢复。最终完成全部 200 道主诊断首次尝试，保留全部 5 次服务失败，没有用成功重试替换。

## 200 题最终结果

以下统一以 200 道主诊断题为分母，包含服务失败，不仅统计成功请求：

| 阶段 | 全部支持证据完整 | 比例 |
| --- | ---: | ---: |
| 向量 Top5 | 160/200 | 80.0% |
| 向量 Top10 | 179/200 | 89.5% |
| 向量 Top20 | 192/200 | 96.0% |
| 向量 Top40 | 192/200 | 96.0% |
| 重排头部 Top5 | 170/200 | 85.0% |
| 重排头部 Top10 / 最终请求 Top10 | 182/200 | 91.0% |

互斥归因：证据完整 **182**；候选已含完整证据但最终选取丢失 **10**；正常请求召回缺证据 **3**；服务超时 **5**；入库/映射不可用 **0**。合计 200。

195 道未降级请求中，现有 rerank Top10 相对向量 Top10 为改善 8、退化 5、不变 182，净增 3 题（全题分母 +1.5 个百分点）。**这是原系统已有 rerank 的阶段比较，不是本次新增算法的收益**。Top5 比较只是同一候选快照的前缀覆盖，不是实际低 TopK 配置的独立性能实验。未比较回答质量、token 成本收益或延迟改善。

结论：不能再用固定题内候选的 99% 来概括当前真实公开池表现，也没有理由仅凭样本量继续盲目扩大语料。10 个选取丢失案例全部是 `bridge` 多跳题；下一步优先检查中间实体/关联证据是否因对原问题相关性较低而被截断。这是可检验的机制假设，不是已经证明的根因或改进收益。当前不重新调旧覆盖策略、不打开冻结测试，不把服务超时混入算法质量退化。

可追溯例题：`hotpot-public_dev-5adc5e1255429947ff173938`（电影主演的出生年份）、`hotpot-public_dev-5ae791db5542994a481bbdab`（歌曲演唱者的出生时间）。逐题分类在 `raw-dev200-score.json` 的 `per_question` 中，原问题和阶段候选在 `raw-dev200-first-attempts.jsonl` 中。

## 验证与费用

- Python 工具测试 11 项通过；Java 隔离、捕获和相关检索回归 22 项通过。
- Spotless 检查通过；首次静态 mock 测试不适配项目 mock maker，已改为真实鉴权拒绝及独立隔离检查测试后通过，未更改全局测试配置。
- 在线调用已经发生，提供商 token/实际账单未自动对账，不能宣称本阶段零调用或零费用。完成 200 次主诊断 API 首次尝试、5 次完整池原问题冒烟、5 次改写冒烟和 1 次不完整池冒烟；这些是应用请求次数，不冒充提供商计费调用计数。只有公开正文和问题参与模型请求，无非公开工业数据上传。
- 百炼北京 qwen3-rerank 公示输入价为 0.5 元/百万 token，见 [官方模型说明](https://help.aliyun.com/zh/model-studio/qwen3-rerank)。SiliconFlow 国际页面的美元价格不能当作国内账户实际价格；本轮不使用该换算伪造账单。未生成 200 题回答或展开付费参数搜索。
