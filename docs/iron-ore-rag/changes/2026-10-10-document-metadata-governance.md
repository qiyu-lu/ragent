## 改动目的与发现过程

语料里有几组"近领域"文档：全铁有钛铁矿精矿的重铬酸钾滴定法（YS/T 360.2）和铁矿石的三氯化钛还原法（GB/T 6730.5）两份，硅有铁矿石（GB/T 6730.10）和硫铁矿（GB/T 16574）两份，另有同属钛铁矿精矿的全铁与氧化亚铁、同一份标准里的取样与制样。基线 `S1-base` 上，混淆题是各题型里最差的：调参集（8 题）Hit@5 0.667，测试集（7 题）0.429。

文档本身不带结构化信息：标准号、代替的旧标准、检测对象、被测组分都只写在正文里。检索时分不出"这块属于钛铁矿精矿的标准"；同一标准有新旧两版时也没有地方标出哪版现行。领域术语有多种写法（"全铁 / 全铁量 / 总铁 / TFe"），没有统一的表。

## 方案取舍与选择理由

- **文档级元数据，不做块级标签**：混淆发生在文档之间，文档级的"检测对象 + 组分"足够区分。RAGFlow 的标签集两阶段打标（`extractor_tag.go`）收益小，按计划 §8 不做。
- **规则抽取 + 人工确认**：标准号、发布年、代替的旧标准用正则从 PDF 文字层的封面与前言抽。文字层优先，因为 2014 版两份 GB/T 的解析结果里"代替"后面的标准号整段丢了；文字层找不到再找解析结果开头，因为 2007 版全铁的页眉在文字层里是乱码。检测对象 / 组分 / 方法用术语表匹配标题。抽到的值是草稿（`source=extracted`），确认接口改成 `confirmed`，重新分块时保留已确认的值。不用 LLM 抽取：7 份文档规则就能抽全，结果可复现。
- **时效性在读时计算，不回写**：同一知识库里同一标准（去掉年份的标准号相同）有多个版本时，年份最新的为现行，其余标"已被代替"；另一份文档的"代替"清单列出了本文档的标准号，也算被代替。新版本删掉后，旧版本自动恢复为现行。
- **术语表是一份 CSV**（术语、同义写法、类别：检测对象 / 组分 / 方法 / 试剂 / 仪器 / 标准号）：入库抽元数据、检索时识别查询、阶段 3 当分词词典，三处共用。匹配前两侧都转成比对形态（NFKC、去空白、ASCII 小写），再做最长匹配，所以"钛铁矿精矿"不会被拆出"铁矿"，"硫酸亚铁铵"不会被认成"硫酸"。
- **加权而不是过滤**：查询里识别出的检测对象或组分只作为加分，不把检索范围限定到对应文档。识别错的时候（见下文的调研题），硬过滤会把正确文档整个排除。借鉴 RAGFlow 的"知识库 pagerank 加到分数"（`dataset.go:118`），粒度换成文档。
- **加权放在 Rerank 之后、只动重排头部**：最终分 = 重排分 + β × 匹配度。匹配度是查询提到的维度（检测对象、组分）里文档对上的比例：问"钛铁矿精矿的全铁"时，YS/T 360.2 得 1，GB/T 6730.5（铁矿石、全铁）得 0.5。重排头部以外的融合尾部没有重排分，和头部的分数不可比，所以不动。β 在 {0.1, 0.2, 0.3} 里按调参集选。

## 实现与调用链

- 入库：`ParseQualityStage` 末尾调用 `DocumentMetadataExtractor`（标准号、年份、代替从文字层与解析结果抽；对象 / 组分 / 方法由 `TermDictionary` 匹配标题），经 `DocumentMetadataCodec` 写进 `t_knowledge_document.doc_metadata`（JSONB，与解析审计同列）。
- 核对：`GET /knowledge-base/docs/{docId}/metadata` 读，`PUT` 同一路径确认（需 MANAGE 权限）。评测侧 `eval/kq/doc_metadata.py export | confirm` 批量导出、确认。
- 读取：`DocumentGovernanceResolver` 按文档 ID 批量取元数据，算时效性；`SourcesAssembler` 把标准号、"已被代替"、解析复核结论放进 `SourceRef`，前端 `SourcesPanel` 显示。
- 检索：`MetadataBoostPostProcessor`（order 11，Rerank 之后）。`rag.search.metadata-boost.enabled` 默认 false，`beta` 默认 0.2。同一标准的新旧版本都在头部时，旧版本的块压到新版本最好的块之下。
- 术语表：`bootstrap/src/main/resources/kq/terms.csv`，60 条，位置可用 `rag.knowledge.terms-location` 覆盖。
- 测试：`DocumentMetadataExtractorTest`、`DocumentMetadataCodecTest`、`DocumentGovernanceResolverTest`、`MetadataBoostPostProcessorTest`。

## 验证与效果

**元数据抽取**：7 份文档（6 份标准 + 调研表）的标准号、代替、检测对象、组分、方法，核对时全部按抽取值确认，没有改动（导出文件与确认输入的 SHA-256 相同）。术语表 `note` 列标出的 3 处待核对项（铁精矿是否并入铁矿石、"缩分"是否保留、调研表组分的同义写法）没有改。时效性规则在本语料上没有样本：7 份里没有同一标准的新旧两版，只有单元测试。

**查询侧加权**：`S2-boost(β)` 对 `S2-gate`，同一个库 `ragent_eval_kq_s2`、同一份服务端代码，回放同一批子问题；调参集 61 题（可答 53），每个 β 3 次。门槛写定于 `kq-s1`：总体 MRR 提升 ≥ 0.022，且数值题 Hit@5 降幅 ≤ 0.045。

| 臂 | 总体 MRR | 总体 Hit@5 | 数值题 Hit@5 | 数值题 MRR | 混淆题 MRR（8 题，只报告） |
| --- | ---: | ---: | ---: | ---: | ---: |
| S2-gate（β = 0） | 0.690 | 0.755 | 0.758 | 0.674 | 0.375 |
| β = 0.1 | 0.671 | 0.761 | 0.727 | 0.636 | 0.400 |
| β = 0.2 | 0.699 | 0.755 | 0.773 | 0.682 | 0.393 |
| β = 0.3 | 0.673 | 0.736 | 0.742 | 0.652 | 0.410 |

总体 MRR 的变化是 −0.019、+0.009、−0.018，都没到 0.022，三个 β 都"未证实"。按规则不跑测试集，boost 保持默认关闭。

按题看，加权只在少数题上起作用，作用方向有正有负：

- **救不回不在池里的块**：`con-03`、`con-07`、`con-11` 的锚点块在每个 β 下都不在 20 个候选里（后两题是 S2 重新入库后掉出向量召回前 20 的）。加权只改重排头部的顺序，不往池里加东西。
- **分不开同一文档里的块**：`con-01` 的前两名都是 YS/T 360.2 的块，加分相同，锚点块始终排第 2（MRR 0.5）。
- **查询点名了组分、问的却是调研表时，会把标准压到调研表前面**：`svy-13`（"全铁检测预还原时三氯化钛要加到什么程度"，答案在调研表）重排分最高的是调研表的块（0.950），GB/T 6730.5 的块因"全铁"加分后排到它前面，MRR 1.00 → 0.33 / 0.17 / 0.12（β = 0.1 / 0.2 / 0.3）。`con-15`（调研里的现场缩分 vs 国标手工缩分）同理，"缩分"命中组分"取样制样"，MRR 0.33 → 0.20 / 0.14 / 0.11。β 越大压得越多。
- **帮到的**：`con-13`（制样阶段的干燥温度）MRR 0.67 → 1.00，三个 β 都是。

`num-si-05`、`pro-tfe-03` 等几题只在个别 β 下变化，不随 β 单调，按运行噪声看待。

## 限制与停止状态

- **术语识别是字面最长匹配，不做消歧**："调研""现场"这类指向调研表的说法不在术语表里，调研表的组分"工序与设备"也很少被问到，所以问调研表的题经常匹配到标准。改进方向是把"调研表 / 现场"作为检测对象维度加进术语表，或者只在查询同时提到检测对象和组分时才加权。两者都没做，β 的网格也只有 3 个值。
- **混淆题的主要缺口在召回池**：8 题里 3 题锚点块不在候选池，这是加权解决不了的。阶段 3 的中文全文通道针对的就是池子这一层。
- **样本量**：混淆题每个集只有 7～8 题，只报告，不判定。
- **时效性**没有在真实的新旧版本上验证，只有 `DocumentGovernanceResolverTest`；来源面板的"已被代替"标记没有自动化测试。
- 元数据核对没有改动任何值，说明规则在这 7 份上抽得全，不说明换一批文档时也抽得全。
