# 改动标题

## 记录信息

| 项目 | 内容 |
| --- | --- |
| 日期 | `YYYY-MM-DD` |
| 所属阶段 | 阶段 N |
| 状态 | 计划中 / 已实施 / 已验证 / 已回退 |
| 分支 | `branch-name` |
| Git 提交 | `commit` |

## 问题与边界

说明可观察的问题、期望行为，以及本次明确不处理的范围。

## 实施内容

列出关键行为变化和主要文件。不要粘贴大段源码。

## 验证

记录可重复执行的测试命令、关键结果和人工验收方法。失败或未覆盖项也应明确保留。

## 数据与兼容性

说明数据库、对象存储、缓存、消息队列、配置或 API 是否需要迁移，以及旧数据如何处理。

## 回滚

记录安全的 Git 回滚方式，以及代码回滚后是否还需要处理数据或配置。默认优先使用 `git revert`，不要把会丢失工作区内容的命令写成常规步骤。

## 后续事项

只记录仍与本改动直接相关的限制；新的研究目标应进入下一阶段文档。
