## 怎么区分已经实现与扩展设计

项目答案优先依据 [flow-notes](../flow-notes/01-login-and-access.md)，再用源码核对关键分支。历史结果以对应实验记录与脚本口径为准；一般技术原理附官方文档或论文链接。笔记与源码不一致时，需要明确指出差异。

“源码里有”“主配置开启”“隔离评测跑过”“生产验证过”是四种不同证据。当前目录存在尚未提交的实验代码和笔记，这套材料不将其自动表述为已上线能力。多租户权限、生产容量、故障恢复等设计题中提出的方案，也不能当作本项目已经完成的工作。

优先记住这些容易被追问的地方：

- 基于开源 Ragent 构建，先讲继承的系统能力，再讲自己实际修改了什么。
- 上传文档与触发摄取是两个动作；RocketMQ 负责异步交接，解析、分块和向量化由消费者调用的业务链执行。
- 1024 是表格分组目标，单个不可拆字段仍可能超限；字符数、切片数和模型 token 数不是同一预算。
- 主配置的公平回填关闭；可选 BM25 / RRF（按排名融合）不能直接说成默认聊天链路。
- 知识库范围路由不等于权限校验；来源编号存在不等于已经证明每句话都被证据支持。
- 建议方案、局部测试与真实服务运行分别表达；无法确认的吞吐、费用和用户规模不补造。

## 模拟面试用法

第一轮用 30 分钟，只练项目定位、三项贡献和数字口径。第二轮选一条后端主线连续追问，例如“事务消息 → 重复消费 → 幂等 → 崩溃恢复”。第三轮把一个故障从用户现象追到具体阶段，例如“答案缺一个检测条件”依次检查原文件、切片、候选、最终上下文与模型生成。

能说明“为什么这样做、替代方案是什么、怎样验证、哪里还没有保证”，比逐字背完全部答案更有用。
