## 2. 先用一句话识别项目

这是一个 Java 17、Spring Boot 模块化单体的工业知识应用：把 XLSX、PDF、Markdown 等资料转换为可追溯证据，通过问题理解、检索、重排和流式模型调用回答问题，并把回答中的证据进一步约束为可审核的铁矿任务草案与版本差异。

主要输入、输出和价值如下：

| 维度 | 内容 |
| --- | --- |
| 输入 | 本地/远程文档、用户问题、会话历史、知识库/意图配置 |
| 离线产物 | 文档元数据、结构块、检索块、Embedding、索引、摄取状态与耗时 |
| 在线产物 | SSE 回答片段、来源列表、grounding 快照、Trace、会话消息 |
| 业务产物 | 带证据白名单的任务草案、审批状态、模拟执行记录、工作簿版本差异 |
| 用户价值 | 从“查资料”推进到“知道答案来自哪份资料、哪一版、哪些块，并在人工门禁后形成受控对象” |

它不是已验证的生产系统，也不是让模型直接控制设备的 Agent。当前默认检索仍是向量通道；关键词、图、Web 等是可选适配器。ROS 只到可选 dry-run 边界。

## 3. 当前 checkout 的能力快照

### 3.1 默认在线链路

```text
上传/登记文档
  -> RocketMQ 事务消息调度摄取
  -> 解析与结构感知切分
  -> Embedding
  -> PostgreSQL + PGVector 索引

用户问题 + 会话历史
  -> 问题改写/拆分
  -> 意图与作用域
  -> 向量召回（默认）
  -> 去重 -> 融合 -> 候选池截断 -> 元数据增强 -> 重排
  -> 请求级选择（默认仍为旧前缀路径）
  -> 来源/grounding -> Prompt -> LLM SSE
```

需要影响能力判断的当前配置边界：

- `ragent.engine.type=workflow`；源码中的 Agent/Profile/MCP 能力不能整体等同于完整 ReAct 主链。
- `storage.vector=pg`，`keyword=none`，`graph=none`；检索通道配置中只有向量开启。
- Embedding 表维度固定为 1536；换模型前必须同时检查模型输出、数据库列和既有索引，不能只改模型名。
- `request-level-refill-enabled=false`：公平回填实现存在，但历史 D2 门槛失败后未成为默认。
- 独立 `DeterministicContextSelector` 只用于 Java 回放/评测，未注入默认聊天链路。
- `ragent.eval.enabled=true` 出现在当前主配置；普通评测入口受全局登录保护，但不像 pooled 入口那样同时要求专用 profile、开关、管理员与隔离库。这是当前配置审查项，不代表它已对公网部署。

### 3.2 已有但不应包装成默认成果的能力

| 能力 | 当前状态 | 面试表达边界 |
| --- | --- | --- |
| Elasticsearch BM25 + Java RRF | 适配器和隔离评测链存在，默认聊天关闭 | 可讲真实公开集配对结果，不能说生产默认已切混合检索 |
| LightRAG 图通道 | 适配器与单测存在，默认关闭 | 可讲接口和隔离限制，无当前业务效果证据 |
| Web 检索 | 通道存在，默认关闭 | 不应说离线知识不足时一定联网兜底 |
| 可配置摄取管线 | 独立任务/节点引擎存在 | 知识文档上传的 `pipeline` 执行分支当前明确不可用；主链是固定内核 |
| 上下文覆盖选择器 | 回放实现与负结果存在 | 只能称研究组件；冻结开发集没有超过简单基线 |
| ROS1 网关 | 结构化编译、白名单与 dry-run 路径存在 | 没有真实设备闭环与安全认证证据 |

## 5. 推荐学习路线

### 5.1 面试前 30 分钟

1. 读 [08 的两版项目口述](08-interview-playbook.md#project-pitch-short)。
2. 看 [系统地图](08-interview-playbook.md#system-map) 和 [推荐讲解顺序](08-interview-playbook.md#presentation-order)。
3. 从五个核心模块中选两条最贴岗位的链，各背“短口述 + 主链 + 三个边界”。
4. 最后读 [事实修正清单](09-core-business-chain-review.md#12-先记住这些事实修正)。

### 5.2 后端开发路线

依次学习：摄取任务的事务消息与状态 → 索引替换和跨存储一致性 → SSE 生命周期与取消竞态 → 任务状态机和唯一约束 → 登录、对象级授权与评测端点隔离。重点回答“重复请求、实例重启、外部依赖失败时系统留下什么状态”。

### 5.3 AI 应用路线

依次学习：结构解析/切分 → Embedding 与 HNSW → BM25/向量/RRF/重排 → 查询拆分和上下文选择 → Prompt/引用 → 分层评测 → Prompt Injection、知识更新与图/多跳扩展。重点回答“程序成功但答案质量失败时怎样归因”。

### 5.4 深挖一条链的方法

每条核心链按同一顺序复习：

```text
先讲业务问题
  -> 复述 30～60 秒方案
  -> 按时间顺序走端到端链
  -> 解释一个关键机制和一个替代方案
  -> 给出一个失败模式和恢复方法
  -> 说明当前证据与尚未验证项
```

不要从 Controller、表名或 YAML 默认值开场；这些只在追问到实现约束时出现。

## 6. 合上文档后的自测

### 项目全局

- 能否用一句话说出用户、输入、输出和边界，而不是只说“这是 RAG 项目”？
- 能否解释为什么它是模块化单体，以及 PostgreSQL、PGVector、Redis、RocketMQ、对象存储分别保存什么？
- 能否把默认能力、可选适配器、评测专用 WIP、历史实验分开？

### 摄取与知识生命周期

- 为什么上传登记和摄取执行分成两个动作？事务消息解决哪一段一致性、又不解决哪一段？
- `content` 与 `embedding_text` 为什么分离？表格合并单元格和超宽稀疏行怎样影响检索？
- 文档重建时关系块、向量、关键词、图索引怎样避免半新半旧？当前实现哪里仍需补偿？

### 检索与生成

- 双塔 Embedding、BM25、Cross-Encoder 重排的输入、计算位置和成本差异是什么？
- RRF 为什么用名次而不是直接加原始分数？请求级 TopK 为什么可能欠填或被噪声填满？
- 来源列表、grounding 快照和回答里的引用各自能证明什么，不能证明什么？

### 可靠性、安全与评测

- SSE 断开、用户停止、模型错误同时发生时，哪个条件更新决定最终状态？
- 登录为什么不等于知识库对象级授权？向量检索的 ACL 应在哪些层都生效？
- 能否区分解析成功、召回成功、选择成功、回答忠实、端到端任务成功和线上 SLO？
- 能否解释为什么负结果、失败请求和重复运行的波动必须保留？

## 7. 使用边界

- 文档中的第一人称只用于模拟候选人口述，不表示个人贡献归属。
- 当前仓库里的企业原文、真实题目、密钥、模型响应和数据库快照位于忽略目录或外部环境；不要从聚合报告反推或公开它们。
- 公开数据集结果只能说明固定数据、固定提交与固定评测协议；不能外推中文工业问答、生产吞吐或成本。
- 以后源码或配置变化时，先更新本页“能力快照”，再更新 08 的口述和 09 的相应链路；不要直接覆盖历史评测记录。
