## 离线检查结果

- 派生 XLSX 只有一个“浓度检测”工作表，有效区为 `A1:H25`；逐单元格与来源 `B2:I26` 比较，显示值无差异。
- 派生 XLSX 不包含图片、公式、批注或超链接，作者与最后修改者为空。
- 项目原生 `ExcelDocumentParser` 将其解析为一个标题块和一个表格块；默认分块配置产出 9 个块。
- Markdown 对照经项目原生解析器和默认分块配置产出 2 个块。
- 两种格式的最终 `embeddingText` 均包含定义、浓度调整、浓度壶净重公式、烘干称重公式、`105±5 ℃` 和中心实验室差异六类关键事实。

离线检查用于确认样本具备运行条件；真实 Embedding、召回、回答和来源验证结果见下文。原生 Excel 快速解析仍按“一工作表一张规整表、首行作为表头”处理，不理解工作表内部的多个语义分区。

## 固定问题集

每个问题使用独立新会话。可回答问题必须同时满足“召回片段包含依据、答案与依据一致、返回正确样本文件名”；无答案问题必须明确说明资料未提供，不能补造数值或品牌。

| ID | 问题 | 期望事实或行为 | 原始证据 |
| --- | --- | --- | --- |
| Q1 | 铁矿石检测中的矿浆浓度指什么？ | 干铁矿粉重量占整份矿浆总重量的比例，以百分比表示 | `D3` |
| Q2 | 矿浆浓度偏高或偏低时分别如何调整？ | 偏高时加水稀释，偏低时减少补水 | `G3` |
| Q3 | 现场采用浓度壶称重法时有哪些步骤？ | 确认空壶重量、取样装壶、称重计算净重、查表记录浓度，顺序正确 | `F8:F11` |
| Q4 | 浓度壶法如何计算矿浆净重？ | 矿浆净重 = 总重 - 空壶重 | `H8`、`F10` |
| Q5 | 烘干称重法如何计算浓度？ | 浓度 = 干矿样质量 / 湿矿浆质量 × 100% | `H12`、`F16`、`F21` |
| Q6 | 中心实验室的烘干温度是多少，它与现场方法的目标有何差异？ | 105±5 ℃；中心实验室追求精准并用于结算、品控，现场以快速指导生产为主 | `E6`、`E12`、`E17`、`F19`、`B24` |
| Q7 | 文档规定的浓度检测允许误差具体是多少？ | 无答案；文档只说允许合理误差，没有给出具体数值 | 无 |
| Q8 | 在线浓度计应该采用哪个品牌和型号？ | 无答案；文档没有品牌或型号 | 无 |

Q5 按调研材料原文验收，但原文口径并未完全闭合：`H12` 将湿重、干重分别写成“矿浆 + 采样桶总重”和“干矿样 + 采样桶总重”，同时写“浓度 = 干重 / 湿重 × 100%”；`F16`、`F21` 又使用“干矿样质量 / 湿矿浆质量”。两者是否都应先减去采样桶空重再计算，需由业务审核确认。本阶段只验证模型召回并复述了当前固定公式，不自行勘误。

## 执行方法

1. 使用与阶段 0 相同的本地中间件、模型、Embedding、摄取参数和 Prompt，创建一个临时知识库。
2. 先上传 XLSX，等待异步摄取完成，检查分块正文是否包含六类关键事实，再逐题验证 Q1–Q8。
3. 保存结果后删除 XLSX，并确认对应分块和向量已清理；再上传 Markdown，按相同步骤执行。
4. 每题使用新会话，避免上一题的会话记忆影响结果。运行环境偶发失败可以排除原因后重试一次；内容失败不通过反复调参或改问题掩盖。
5. 删除临时会话、文档和知识库，不保留评测数据污染后续实验。

## 结论规则

- 两份样本均通过：确认原生 XLSX 对这个有限样本可用，不外推为支持完整复杂工作簿。
- Markdown 通过而 XLSX 未通过：阶段 2 采用受控 Markdown，记录 Excel 解析缺口，但本阶段不改解析器。
- 两份样本均未通过：保留阶段 1，不进入领域数据模型开发，先报告共同的检索或运行基线问题。

本次命中第一条规则：原生 XLSX 对这个单工作表、有限区域的样本可用。该结论不能外推到原调研工作簿中的图片、排班表、多语义分区或其他复杂工作表。Markdown 在本样本中形成的语义结构更清楚、分块更少，但两种格式的固定问题均全部通过，单次小样本不足以宣称 Markdown 的回答质量更高。

因此不要求人工把完整调研工作簿转换成 Markdown。后续如需纳入复杂工作表，优先保留原 Excel 作为来源，再按工作表和业务主题制作可审核的有限派生样本；是否采用原生 XLSX 或受控 Markdown，应由新的代表性样本结果决定，而不是现在建设通用转换器。
