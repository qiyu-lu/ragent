# 铁矿 RAG 小型评测

这套工具把基线评测放在当前仓库外部执行，不修改冻结的 `bcfba62` 基线源码。它复用两版都已有的 `GET /rag/eval`，同时采集主实验的完整 SSE 回答，目标是形成可复查的小样本数字，而不是宣称行业级基准。

## 固定口径

- 3 份文档：完整 V1.2 调研 XLSX、一份原生文本铁矿石国标 PDF、一份扫描/异常文本层钛铁矿行业标准 PDF。
- 24 道正式题：每份文档 6 道可回答题、3 道近领域混淆题、3 道不可回答题。
- 15 个解析锚点：每份文档 5 个，用来单独判断解析/OCR，不与回答正确率混在一起。
- 之前阶段 1 的 8 道问题只作开发冒烟，不进入本数据集。
- 主检索指标为文本锚点 Hit@5，同时报告全部锚点 Hit@5、Anchor Recall、MRR、Context Precision、文档指标和 P50/P95 延迟。
- 无意图组不计算“意图准确率”；有意图组额外计算 18 道单文档题的 Top-1 意图准确率和路由纯度。
- OCR 不称为“回答准确率”，只比较解析锚点恢复、块形态和 12 道 PDF 题的检索结果。
- 只有 B0 与 C-final 各运行 24 个完整回答，共 48 条，由人工盲评。

真实题目、答案事实点、原始文档、响应、数据库备份都在 Git 忽略的 `local-data/eval/`。仓库中只保存通用程序、Schema、脱敏示例和评测方法。

本次评测已获得完整 V1.2 XLSX 发送到当前配置的外部 Embedding/Chat 服务的授权；这不等于允许公开原文件、真实问题或逐题答案。PDF 解析还会调用配置的 MinerU 服务。

## 数据集字段

正式 JSONL 遵循 [`dataset.schema.json`](dataset.schema.json)。核心字段为：

- `reference_docs`：文件名去后缀，与 `/rag/eval.retrievedDocIds` 对齐。
- `reference_anchors`：应出现在召回块中的稳定短语，避免使用每次入库都会改变的 chunk ID。
- `expected_facts`：人工判断必须覆盖的事实。
- `forbidden_claims`：一旦回答出现就不能严格通过的越界结论。
- `expected_kbs`、`expected_intent_ids`：只为意图开启组计算路由和 Top-1；后者填写接口实际返回的 `intent_code`（如 `eval-iron-ore`），不是数据库主键。

严格回答通过规则：

- 可回答题必须同时满足事实正确、证据支持、来源正确、没有禁止结论。
- 不可回答题必须正确说明资料不足，且没有编造禁止结论。
- 任一字段失败，整题严格通过记为 0；不得用部分分掩盖幻觉。

## 实验臂

| 臂 | 设置 | 自动检索 | 完整回答 |
| --- | --- | ---: | ---: |
| B0 | 基线；意图关；OCR 关；默认分块 | 24 | 24 |
| B1 | 基线；意图开；其余同 B0 | 24 | 0 |
| B2 | 基线；意图关；OCR 开 | 12 道 PDF 题 | 0 |
| C0 | 当前版；意图关；OCR 关；默认分块 | 24 | 0 |
| C1 | 当前版；意图开；其余同 C0 | 24 | 0 |
| C2 | 当前版；意图关；OCR 开 | 12 道 PDF 题 | 0 |
| C-final | 当前版；由固定门槛选择意图/OCR | 24 | 24 |

模型固定为 `qwen3-max`、`qwen-emb-8b`、`qwen3-rerank`。本地评测 YAML 将每一类候选限制为一个；调用失败即该实验失败，不允许静默降级。

D0、D1、D2 是冻结主实验后的诊断，不追加到 B/C 主实验臂：D0 隔离检索代码，D1 干净重建组合验证分块与检索，D2 则复用 D1 同一数据库并固定其 `subIntents`，只比较请求级公平回填 off/on。

## 何时重置

| 变化 | 重新入库 | 清 Redis/重启 |
| --- | --- | --- |
| 重复查询或完整回答 | 否 | 否 |
| 意图关 → 开 | 否 | 是 |
| OCR 关 ↔ 开 | 是，至少 PDF；本评测为状态纯净重建三份文档 | 是 |
| `maxChars`、`overlapChars`、`rowsPerChunk` | 是，全部文档 | 是 |
| TopK、rerank 配置 | 否 | 重启 |
| `request-level-refill-enabled` off ↔ on | 否；D2 必须复用同一 D1 库 | 重启 |

本轮分块固定为 `1024 / 128 / 50 / 3`。`ChunkerSettings.strategy` 在两版后端均为废弃兼容字段，后端不会读取，因此不安排伪“策略对比”。只有正式结果中至少两题明确属于跨块失败时，下一版才在当前代码上探索 `512/64`、`1024/128`、`2048/256`，不得回填本轮成绩。

## 结果使用边界

- 同配置的 B0 与 C0 说明代码版本差异；B0 与 C-final 只能称为端到端系统对比。
- 必须分 XLSX、原生 PDF、扫描 PDF、跨领域和不可回答题报告，不能只给有利的总体平均。
- B0 和 C-final 应在 48 小时内完成，减少在线模型漂移；很久以后的版本可以继续比较冻结检索结果，但不能把旧回答差异全部归因于代码。
- 固定 `subIntents` 只隔离在线改写；embedding、intent 和 rerank 仍是在线调用，所以 D2 使用三次重复和中位数，不能把一次候选排序当作完全确定性结果。
- 简历表述应明确为“3 类文档、24 道固定问题的小型评测”。
